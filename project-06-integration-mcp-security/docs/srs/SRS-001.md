## 1. Purpose

This document specifies the requirements for P06: an integration layer that composes P05's security controls (content isolation and PII scanning) with P03's agentic research pipeline. The integration must be demonstrably functional, testable, and leave both parent projects independently runnable.

The SUT (System Under Test) throughout this portfolio is a Jira/Confluence AI assistant operating in a regulated financial services environment. P06 closes the explicit gap identified in P05's threat model: controls are verified in isolation but never exercised on the real data structures produced by the live pipeline.

---

## 2. Scope

**In scope:**
- A P06-owned integration wrapper around P03's `ResearcherAgent` and `Orchestrator`
- P05 security controls active on the P03 execution path
- Integration tests covering the two security wiring points
- A pipeline regression test confirming benign-input behavior is unchanged
- Documentation: design doc, ADRs, lessons learned

**Out of scope:**
- Modifications to P03 or P05 source files (see ADR-003)
- New security controls not in P05
- Production deployment, CI/CD, or containerization
- P02 gateway integration (noted as future extension in lessons-learned.md)

## 4. Functional Requirements

### FR-1 — Content isolation before LLM context

**Statement:** External content retrieved via MCP tool calls shall be sanitized and labeled with trust boundary markers before entering the LLM message context.

**Acceptance criteria:**
- `preprocess_content()` strips zero-width Unicode, hidden HTML, and null bytes from tool result content
- `isolate_chunk()` wraps preprocessed content with `[RETRIEVED FROM: ... | TRUST: external-internal | ID: ...]` markers
- A prompt injection payload present in tool result content is present in the LLM message but is clearly bounded by trust markers, distinguishable from system instructions
- A test demonstrates: same injection payload without markers is indistinguishable from other context; with markers, it is labeled

**Constraint:** The `prepare_retrieved_context()` function cannot be inserted into P03's `ResearcherAgent.run()` loop without modifying `researcher.py`. See ADR-002 for the architectural decision. FR-1 acceptance criteria are verified by testing `content_isolation.py` directly against synthetic `RetrievedChunk` inputs that represent the shape of P03 MCP tool results.

### FR-2 — PII scan before state persistence

**Statement:** Every `ResearchFinding.content` produced by `ResearcherAgent.run()` shall be scanned for PII before the finding is persisted to `state/`.

**Acceptance criteria:**
- `scan_output_for_pii(finding.content)` is called for every finding before `_persist()` is invoked
- If `result.action == "block"`: a `PIIInFindingError` is raised; finding is not persisted
- If `result.action == "warn"`: finding is persisted; warning is logged
- A test with a synthetic `ResearchFinding` containing an SSN (`123-45-6789`) and email produces `has_pii=True`, `action="block"`, entity types `["US_SSN", "EMAIL_ADDRESS"]`
- A test with benign content produces `has_pii=False`, `action=None`

### FR-3 — Pipeline regression (no behavioral change on benign input)

**Statement:** The secure pipeline (P06 wrappers active) shall produce functionally equivalent output to the baseline P03 pipeline for benign research topics. Controls shall be additive only.

**Acceptance criteria:**
- `SecureOrchestrator.run()` completes without error on a benign topic (mocked LLM and tools)
- `state/` contains a finding whose content has been PII-scanned (scan was called, no block raised)
- No additional latency, state changes, or side effects compared to baseline `Orchestrator.run()`

## 5. Non-Functional Requirements

### NFR-1 — P03 independence preserved

`project-03-agentic-mcp` must remain independently runnable after P06 is created. P06 imports from P03; P03 has no dependency on P06.

**Verification:** `cd ../project-03-agentic-mcp && pytest` passes with no changes.

### NFR-2 — P05 independence preserved

`project-05-security-compliance` must remain independently runnable. P06 imports from P05 via sys.path; P05 has no dependency on P06.

**Verification:** `cd ../project-05-security-compliance && .venv/bin/pytest` passes with no changes.

### NFR-3 — Zero modification constraint

No file within `../project-03-agentic-mcp/src/` or `../project-05-security-compliance/src/` shall be modified by P06 work.

**Verification:** `git diff ../project-03-agentic-mcp/src/ ../project-05-security-compliance/src/` shows no changes.

### NFR-4 — Explicit integration surface

The wiring points, type adapters, and interface contracts between P03 and P05 must be documented in `docs/design/DESIGN-001.md` such that a teammate can update either component without breaking the integration.

## 6. Constraints

| Constraint | Source |
|------------|--------|
| P05 has no `pyproject.toml` — cannot use pip path dep syntax | Discovered in Phase 0 recon |
| P03 `ResearcherAgent.run()` assembles tool results inline — no pre-LLM hook | Discovered reading `researcher.py` |
| P03 uses MCP web search/fetch, not Confluence retrieval — `RetrievedChunk` type is a P06 adapter concern | Architecture gap between P05's design assumption and P03's actual implementation |
| Presidio requires `en_core_web_lg` spaCy model (large download) | P05 `requirements.txt` |
